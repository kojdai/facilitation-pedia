# ファシリテーション 学習地図 — A Learning Atlas

**「人と人とが関わるところに生じる問題を扱う営み」を、この地図ではファシリテーションと呼びます。**

会議の進行役という狭い意味ではありません。人が集まれば、話されていることの下で、
聴かれ方・関わり方・力関係といったものが同時に動きます。そのプロセスの側に働きかけて、
その場にいる人たちが自分たちで進んでいけるようにする営み——そう捉えると、
ワークショップも組織開発も対人支援も、同じ根から伸びた枝として見えてきます。

この地図は、それらの手法を**源流から遡ってたどれる**ようにしたものです。
手法を平置きの一覧にせず、どの研究伝統から生まれ、どの概念に属し、
何がその中核なのかが見えることを目指しています。

| 源流 | 中核概念 | 手法 | 人物 | 機関 | 書籍 |
|---:|---:|---:|---:|---:|---:|
| 13 | 38 | 501 | 105 | 9 | 56 |

## 4層の知識モデル

手法を平置きにせず、**重要度と包含関係**を持った階層でたどれるようにしています。

1. **源流（研究伝統）** — 13の研究伝統。最も広いストリーム。
2. **中核概念** — 38の概念（ラボラトリー方式の体験学習・学習する組織・U理論・成人発達論・システム思考など）。源流と手法のあいだの組織化レイヤ。
3. **手法** — 501の手法。各概念に**重要度 tier**（`1`=中核／`2`=主要／`3`=派生）で紐づきます。
4. **系譜・機関** — NTL・MIT Sloan・南山大学など。学派の系譜と、理論間・学者間の影響。

## リポジトリの構造

```
data/                 ← 正本。**直すのはここ**
├── methods/*.md         手法 501（YAML情報欄 + 本文）
├── people/*.md          人物 105（同上）
├── concepts.yaml        中核概念 38
├── disciplines.yaml     源流 13
├── institutions.yaml    機関 9
├── books.yaml           書籍 56
├── relations.yaml       人物・手法間の関係
├── concept-lineage.yaml 概念どうしの影響（A から B が生まれた）
├── roadmap.yaml         源流ごとの読書順路
├── merges.yaml          統廃合された手法の転送先
└── maintenance/         運用メタデータ（表示には使わない）

pipeline/             ← data/ から dist/atlas.json を作る
├── build.py             生成
├── validate.py          書き方の検査（日本語で指摘）
└── test_determinism.py  並び順に依存しないことの検査

dist/atlas.json       ← **生成物**。直しても次のビルドで消えます
```

### 「正本」と「生成物」を分けている理由

`dist/atlas.json` は `data/` から機械的に作られます。**生成物を直しても次のビルドで消えます。**

そして、正本には**人が判断したことだけ**を書きます。
「この手法がどの概念に属するか」「どの源流に連なるか」は、
関連の情報から機械が導き出すので、手で書く必要はありません。
手で書くと必ずずれていき、どちらが正しいのか誰にも分からなくなります。

ただし機械の推測はよく外れます。だから**人が上書きできる**ようにしてあります
（`concept:` を1行足すだけ。詳しくは CONTRIBUTING.md）。
機械は空欄を埋めるだけで、人の判断のほうが常に優先されます。

## ビルド

```bash
pip install pyyaml

python3 pipeline/validate.py         # 書き方の検査
python3 pipeline/build.py            # dist/atlas.json を生成
python3 pipeline/test_determinism.py # 並び順に依存しないことの検査
```

依存は PyYAML のみです。
